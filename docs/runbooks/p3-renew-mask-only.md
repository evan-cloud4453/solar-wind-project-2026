# P3-renew — 격자를 버리고 코로나홀 마스크만 남긴다

P3-renew 는 **새 모델이 아니다.** P3(val 64.203, Public 58.8028)의 모델·손실·증강·
Dataset·학습 루프를 글자 단위로 그대로 두고, *코로나홀 마스크를 무엇으로 요약해서
GRU 에 넣는가* 만 바꾼다.

| | P3 | P3-renew |
|---|---|---|
| CH 피처 | 원반 3x5 격자의 셀별 면적 비율 **15개** | 마스크 전체 스칼라 **1개**(기본) / 5개 |
| 탄도 정렬 | 중앙자오선 **셀** 시계열 | 전 원반 **면적** 시계열 |
| 마스크 규칙 | 193 AND 211 < 0.45 x 원반 중앙값 | 같음(`v1`) 또는 수정본(`v2`) |
| 모델·손실·증강·Dataset·학습 루프 | — | **P3 와 동일** |

노트북은 P3 원본을 다시 타이핑하지 않는다. [build_p3_renew_notebook.py](../../src/builders/build_p3_renew_notebook.py)
가 `Trial/P3/code_p3.ipynb` 를 읽어 **여섯 군데만 손댄다**(제목·3절 markdown·3절 코드·
6절 markdown, 그리고 학습·평가 셀의 한 줄 치환). 나머지 19개 셀은 원본 객체 그대로다.
`python -c` 한 줄로 확인할 수 있다.

## 1. 왜 격자를 버리나

**격자 15개는 면적 1개를 포함한다.** 면적은 셀 면적들의 가중합이니까. 그러니
정보량으로 renew 는 P3 의 부분집합이고, renew 가 이기는 경우는 하나뿐이다 —
**남은 14 자유도가 신호가 아니라 잡음이었을 때.** 격자를 넣어도 점수가 안 오른다면
정확히 그 상황을 의심해야 한다. 이 노트북은 그 가설을 학습 한 번으로 검정한다.

격자가 잡음이 되기 쉬운 이유도 분명하다.

* **셀 경계가 물리와 무관하다.** 자기 중립선도 홀 경계도 아닌, 프레임 좌표 기준의
  사각형이다. 홀 하나가 경계를 걸치면 면적이 두 셀로 임의 분배된다.
* **원반 검출 오차에 민감하다.** 중심이 1~2px 흔들리면 셀별 면적은 크게 요동치지만
  전 원반 면적은 거의 안 움직인다.
* **P3 의 격자는 위경도가 아니다.** `code_p3.ipynb` 셀 8 은 원반 외접 사각형을 픽셀
  좌표로 균등 분할한다. 구면 투영이 아니라서 바깥쪽 셀일수록 실제 태양 면적이
  급격히 줄고, 림 근처 셀은 사실상 시선 방향 왜곡만 담는다.

반대로 renew 가 지는 경우도 분명하다 — **홀의 위치가 실제로 중요했다면** 면적 하나로는
그 정보가 사라진다. 지구와 자기적으로 연결되는 건 중앙자오선 부근 홀이지 원반 전체가
아니기 때문이다. 그 중간을 보고 싶으면 `CH_FEATURE_MODE = "area_shape"` 를 쓴다.
격자처럼 공간을 미리 자르지 않고, **마스크 자신의 1·2차 모멘트**로 위치를 말하게 한다.

| 피처 | 정의 | `area` | `area_shape` |
|---|---|:--:|:--:|
| `ch_area` | 유효 원반 대비 코로나홀 픽셀 비율 | O | O |
| `ch_cx` | 마스크 무게중심의 동서 위치 (반지름 정규화, + = 서쪽 림) | | O |
| `ch_cy` | 무게중심의 남북 위치 | | O |
| `ch_spread` | 무게중심 기준 rms 거리 | | O |
| `ch_depth` | 마스크 안 193 평균 밝기의 기준 대비 어두움 `1 - I/ref` | | O |

## 2. 준비물

**추가 다운로드가 없다.** 이미지 memmap 캐시(`work/cache/128px/*.npy`)는 P3 것을
그대로 쓴다. CH 피처만 새로 뽑는다.

| 캐시 | |
|---|---|
| `work/cache/128px/{split}_images.npy` | P3 것 재사용 |
| `work/cache/ch_{split}_3x5_0.45_128.npy` | P3 격자 캐시. **지우지 않는다** (비교용으로 읽는다) |
| `work/cache/chmask_{split}_{버전}_{모드}_r{비율}_m{여유}_128.npy` | renew 가 새로 만든다 |

파일명이 달라 섞이지 않는다. 노트북은 P3 격자 캐시가 있으면 **renew 면적과의 상관
계수를 한 줄 찍는다** — 둘이 사실상 같은 값이면(r > 0.95) 격자 15개가 애초에
면적 1개를 15번 적어 둔 것에 가까웠다는 뜻이다.

## 3. 실행

```bash
python build_p3_renew_notebook.py
```

그다음 [code_p3_renew.ipynb](../../experiments/p3-renew-mask-only/code_p3_renew.ipynb) 를 위에서부터 실행한다. 건드릴 값은
셀 4(노브)뿐이다.

```python
CH_FEATURE_MODE = "area"    # "area" = 면적 1개 | "area_shape" = 면적 + 모멘트 4개
CH_MASK_VERSION = "v1"      # "v1" = P3 와 동일 | "v2" = ch_mask_check.ipynb 수정 규칙
```

CH 추출은 프레임 수에 비례한다. `v1` 은 P3 격자 추출과 같은 비용이고, `v2` 는 프레임마다
히스토그램 최빈값을 구하므로 몇 배 더 걸린다(그래도 한 번 뽑고 캐시된다).
학습 비용은 P3 와 사실상 같다 — GRU 입력 폭만 15 -> 1 로 줄었다.

## 4. 순서 — 한 번에 하나씩

**rung 0. `v1` + `area`** (기본값). P3 와의 차이가 오직 "격자 -> 면적" 하나다.
여기서 나온 val 을 P3 의 64.203 과 직접 비교한다.

**rung 1. `v1` + `area_shape`.** rung 0 이 P3 보다 나빴다면 "위치 정보가 필요했다"는
뜻이니 모멘트를 얹어 본다. rung 0 이 P3 와 비슷하거나 나았다면 이건 건너뛰어도 된다.

**rung 2. `v2` + (rung 0/1 중 이긴 쪽).** [ch_mask_check.ipynb](../../experiments/p3-renew-mask-only/ch_mask_check.ipynb) 셀 10 의
두 숫자(반경 편중·활동도 상관)가 개선된 걸 **확인한 뒤에** 켠다. `V2_RATIO` 는 그
노트북의 스윕에서 고른 값을 노브에 옮겨 적는다.

> 마스크 수정(`v2`)이 renew 에서 더 중요할 수 있다. 진단이 지적한 림 고리 오검출은
> 격자에서는 가장자리 셀에 몰려서 모델이 그 셀을 무시할 수 있었지만, **면적 하나에
> 섞이면 분리할 방법이 없다.** rung 0 이 지더라도 그게 "격자가 옳았다"는 뜻인지
> "마스크가 고장나 있다"는 뜻인지는 rung 2 를 봐야 갈린다.

## 5. 읽는 법

노트북 9절이 찍는 줄을 P3 와 나란히 본다.

```
공식 RMSE (mean of horizon RMSE) : xx.xxx
[참고] P1 = 68.408 / P2a = 65.663 / P3(3x5 격자) = 64.203
```

**단, 이 val 하나로 결론 내지 않는다.** [RUN_P18.md](p18-chain-cv.md) §1 이 계측한 대로
val 1,199 샘플 = 자전 11.2회전이고, 60 epoch 중 최저값을 고르는 구조라 1 km/s 안팎의
차이는 운으로 설명된다. renew 와 P3 의 차이가 그 정도라면 P18 계측기를 얹는다.

```bash
python build_p18_notebook.py --base code_p3_renew.ipynb --out code_p18_renew.ipynb
```

P18 의 패치 지점이 renew 에서도 그대로 잡히는 것은 확인해 두었다. 다만 P18 노브 셀이
renew 노브 셀보다 **앞**에 들어가므로 `OUTPUT_DIR` 은 renew 쪽(`work/outputs_p3_renew`)이
이긴다. 산출물을 나누고 싶으면 renew 노브 셀의 `OUTPUT_DIR` 을 손으로 바꾼다.

## 6. 남는 한계

* **`ch_depth` 는 마스크가 아니라 밝기를 본다.** "순수 마스킹"에서 한 걸음 나간
  피처라, `area` 모드에서는 아예 빠진다.
* **`AUG_CH_NOISE = 0.05` 는 P3 값 그대로 뒀다.** 정규화된 값에 곱셈 노이즈를 주는
  구조라 피처가 1개로 줄면 증강이 CH 브랜치 전체를 흔든다. rung 0 이 이유 없이
  불안정하면 `Trial/P3/New/code_p3_fix.ipynb` 처럼 0 으로 내리고 `CH_DROPOUT` 을
  쓰는 쪽을 따로 시험한다.
* **`v2` 의 `V2_RATIO` 는 여전히 손으로 고른 상수다.** 진단 노트북 스윕의 무릎을
  골랐다면 그럭저럭 안정적이지만 물리 상수는 아니다.
* **필라멘트를 못 가른다.** 193·211 에서 어두운 건 홀만이 아니다. 자기장 단극성으로
  갈라야 하는데 HMI 자기장이 데이터에 없다.
