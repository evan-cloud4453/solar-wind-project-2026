## 2. 실행 중에 볼 것 세 가지

1. **셀 2-1 시차 표** — 코로나홀 면적 ↔ 타깃 상관의 봉우리가 **3~5일**에 서야 한다.
   여기서 봉우리가 안 서면 원칙 1(마스킹)이 잘못 잡힌 것이니 `CH_THRESHOLD` 를 먼저 본다.
2. **셀 2-2 그림** — 마스크가 원반 안에만 있고 림에 붙어 있지 않아야 한다.
3. **셀 4 홀드아웃 곡선** — 내려가다 평평해지면 정상. 계속 내려가면 `MAX_EPOCHS` 를 늘린다.

## 3. 판정

셀 5 가 `persistence` 와 나란히 찍는다.

* **persistence 를 못 이기면 제출하지 않는다** (셀이 경고를 찍는다).
* val 은 P3 = 64.203(Public 58.80), P1 = 68.408(Public 62.34) 이 눈금이다.
  다만 [CODE_REPORT §1.5](../code-report.md) 대로 **val 순위 = Public 순위가 아니다.**
  val 이 P3 보다 2~3 km/s 나쁘면 제출을 재고하고, 비슷하거나 좋으면 올려 볼 값이 있다.

## 5. 만질 노브 (셀 0)

먼저 볼 순서대로.

| 노브 | 기본값 | 의미 |
|---|---|---|
| `CH_THRESHOLD` | 0.45 | 원반 중앙값 대비 이 배수보다 어두우면 코로나홀. **가장 지배적인 값** (P5 확인) |
| `CH_UNION` | True | `False` 로 두면 옛 P3 의 교집합 규칙. 합집합과 비교해 볼 가치가 있다 |
| `LAT_SIGMA_DEG` | 40 | 작을수록 극지방을 더 세게 깎는다 (30 = 적도 편중, 60 = 거의 균등) |
| `TRANSIT_HOURS` | (72, 96, 120) | 셀 2-1 이 추정한 전달시간 중앙값이 이 범위 밖이면 여기를 옮긴다 |
| `MAX_EPOCHS` | 30 | 홀드아웃 곡선이 끝까지 내려가면 늘린다 |
| `SEEDS` | 3개 | 분산만 줄인다. 시간이 없으면 1개로 줄여도 구조는 같다 |

## 6. 한계 (알고 쓴다)

* **위도는 겉보기 위도다.** B0 각(±7°)과 투영을 무시했다. 원칙 1을 단순하게 지키기 위한 선택.
* **경도는 CNN에게 맡겼다.** 중앙 자오선 가중을 손으로 넣지 않았다 — 전달시간 정렬이
  경도 효과를 시간으로 대신 흡수한다는 가정이다.
* **원반은 train 평균 영상 기준 고정**이다. P7 이 잰 프레임별 반지름 변동 6.4% 는 무시한다.
* **epoch 은 train 뒤쪽 15% 홀드아웃 한 번**으로 고른다. 폴드 반복이 없으므로 ±1 epoch 의
  분해능은 없다. 그래도 val 로 고르는 것(P6 의 실패)보다는 안전한 쪽이다.
