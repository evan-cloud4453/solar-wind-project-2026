## 0. 먼저 정직하게 — 1일로 1위는 어렵다

물리 피처 확장이 옳은 방향이라는 판단에는 동의한다. 근거는 보고서 §5.2 그대로다.
CNN 은 네 번 반증됐고(P2·P3·P6·P10), 최고 제출은 CNN 없는 순수 물리 피처 모델이다.
**다만 남은 시간이 1일이면 "근본 개선"과 "확실한 개선"의 배분을 바꿔야 한다.**

| 목표 | 필요 Public | 이 계획의 달성 확률 (주관) |
|---|---:|---:|
| 20위 (58.30) | −0.50 | ~90% |
| 9위 (56.80) | −2.00 | ~45% |
| 3위 (56.06) | −2.74 | ~20% |
| **1위 (55.59)** | **−3.22** | **~10~15%** |

기대 착지점은 **56.0~57.3 (3~12위)** 이다. 1위는 아래 "천장" 레버 중 하나가
크게 터져야 나온다. 그 확률을 최대화하는 것이 이 계획의 목적이고,
동시에 **바닥이 58.80 아래로 절대 안 내려가도록** 순서를 짠다.

### 바닥과 천장을 분리한다

- **바닥 (floor)** — 적합 파라미터 0개의 시드/설정 평균. 기대 **−1.0 ~ −1.6**, 확률 높음.
  사용자 지적대로 앙상블은 근본 개선이 아니다. 맞다. 그래서 **전략이 아니라 바닥**으로 쓴다.
  물리 피처 멤버들도 어차피 이 평균 안에서 합쳐지므로 두 방향은 경쟁하지 않는다.
- **천장 (ceiling)** — 아래 §2 의 물리 피처. 기대 −0.5 ~ −2.0, 확률 중간.

## 1. 진단 — 지금 물리 피처에 남아 있는 **물리적 오류 3개**

### 1.1 🔴 면적이 진짜 면적이 아니다 (투영 미보정)

```python
disk = np.sqrt((grid_y - cy)**2 + (grid_x - cx)**2) <= r
cell = (lat.astype(np.int32) * FINE_LON + lon.astype(np.int32))[disk]
area[index, level] = np.bincount(cell[selection], minlength=FINE_CELLS) / total
```

픽셀을 **1픽셀 = 1면적**으로 센다. 실제 구면 면적소는 `dA = dpixel / μ`,
`μ = cos(일면중심각) = sqrt(1 − (r/R)²)` 다.

- 코로나홀이 자전으로 림에 가까워지면 **측정 면적이 저절로 줄어든다.**
  같은 홀인데 시계열이 가짜로 변동한다 → CH GRU 가 배우는 시간 구조가 오염된다.
- 림 근처(x/R = 0.9)에서는 실제의 **1/2.3 로 과소계상**된다.
- **장기 horizon 이 정확히 이 손해를 본다.** 72h 타깃의 근원은 T0 기준 동쪽에 있고,
  그 영역이 가장 심하게 눌린 채로 탄도 피처에 들어간다. 우리가 지는 구간과 일치한다.

P10 은 Stonyhurst 투영으로 이걸 고치려 했지만 **±60° crop 과 중앙자오선 ±10° 밴드를 같이
집어넣어서** 2.98 을 잃었다(§1.5). N1 은 같은 투영을 **±75° 로 넓게** 써서 P10 보다 2.05 좋았다.
→ **투영은 죄가 없고 좁힌 것이 죄였다**는 해석을 지지한다.

**이 계획은 crop 없이 μ 보정만 한다.** 픽셀 격자·전 경도·전 원반을 그대로 두고
가중치만 물리적으로 옳게 만든다. P10 의 실패 요인을 하나도 재도입하지 않는다.

### 1.2 경도 셀이 등각이 아니다

```python
lon = np.clip((grid_x - (cx - r)) / (2 * r) * FINE_LON, 0, FINE_LON - 1e-4)   # x 에 선형
```

`x` 등간격은 경도 등간격이 아니다 (`sin φ = x / (R cos θ)`).
`FINE_LON=30` 기준 중앙 셀은 경도 3.8° 를 담고 림 셀은 8.8° 를 담는다 — **2.3배 차이.**
자전이 "셀 인덱스의 균일 이동"이 아니게 되고, 탄도 정렬이 가리키는 소스 경도가 흔들린다.

> 위도는 우연히 괜찮다. `y` 등간격 = `sin θ` 등간격 = **등면적 밴드**다. 손대지 말 것.

### 1.3 코로나홀의 "면적"만 보고 "깊이/형태"를 안 본다

이게 가장 큰 미개척지다. 현재 피처는 셀별 면적 비율 + 밝은영역 비율이 전부다.
그런데 태양풍 속도 예측의 표준 물리 모델(WSA, Arge et al. 2003)에서 속도를 결정하는 항은

```
v = v_slow + v_fast/(1+f_s)^α · [1 − 0.8·exp(−(θ_b/w)^β)]³
```

- `f_s` = 자기장 확장인자 → **자기장 지도가 없어 계산 불가**
- `θ_b` = **발자국에서 가장 가까운 코로나홀 경계까지의 각거리** → **EUV 마스크만으로 계산 가능**

Robbins, Henney & Harvey (2006) 는 `θ_b` **하나만으로** 태양풍 속도를 예측해
자기장 기반 모델에 준하는 성능을 냈다. 우리는 이 항을 **한 번도 넣은 적이 없다.**

물리적 의미가 명확하다. **같은 면적이라도 큰 홀 하나의 중심은 빠른 바람을 내고,
작은 홀 여러 개나 홀 가장자리는 느린 바람을 낸다.** 지금 모델은 이 둘을 구분 못 한다.

그리고 이건 우리가 지고 있는 24~72h 구간 — 즉 **CH 발원 고속류 구간** — 을 직격한다.


### L2 — μ 보정 + 등각 경도 (재추출 없이 즉시 가능)

핵심: **기존 `p7a` 캐시(12×30 fine 격자)를 버리지 않고 후처리로 근사 보정할 수 있다.**

fine 셀 `(i,j)` 안에서 CH 픽셀이 대략 균등하다고 보면, 그 셀의 평균 `1/μ` 는
**기하학만으로** 미리 계산된다. 즉 12×30 가중행렬 하나를 곱하면 끝이다.

```python
def mu_weights(fine_lat=12, fine_lon=30, mu_floor=0.25, side=512):
    """fine 셀별 평균 1/μ. 캐시된 면적에 곱하면 근사 진짜면적이 된다."""
    g = np.linspace(-1, 1, side)
    Y, X = np.meshgrid(g, g, indexing="ij")
    r2 = X ** 2 + Y ** 2
    on = r2 <= 1.0
    mu = np.sqrt(np.clip(1.0 - r2, 0.0, 1.0))
    w = np.where(mu > mu_floor, 1.0 / np.maximum(mu, mu_floor), 0.0)   # ±75° 밖은 버림
    li = np.clip(((Y + 1) / 2 * fine_lat).astype(int), 0, fine_lat - 1)
    lj = np.clip(((X + 1) / 2 * fine_lon).astype(int), 0, fine_lon - 1)
    cell = li * fine_lon + lj
    num = np.bincount(cell[on], weights=w[on], minlength=fine_lat * fine_lon)
    den = np.bincount(cell[on], minlength=fine_lat * fine_lon)
    return (num / np.maximum(den, 1)).astype(np.float32)               # (360,)

MU_W = mu_weights()
train_area_true = train_area * MU_W        # (n, L, 360) 에 그대로 브로드캐스트
```

- `mu_floor=0.25` → **|경도| ≲ 75°** 만 사용. **N1 이 ±75° 로 P10(±60°)을 2.05 이겼다**는
  실측 근거를 그대로 따른다. 림 잡음이 1/μ 로 증폭되는 것도 여기서 막힌다.
- 등각 경도 재비닝도 같은 방식이다. `aggregate()` 가 fine 30열을 3열로 **균등 3분할**하는
  대신, `sin φ = x/R` 기준 경계 `x/R = ±sin 30°` 로 나눈다 → `[0:8], [8:22], [22:30]`.
  (중앙 열이 경도 ±30° 를 담게 된다. 현재는 ±19.5° 만 담는다.)

**비용 0, 재추출 0.** L2 는 오전에 바로 붙는다.
정밀판(픽셀 단위 μ 가중)은 L3 재추출 때 같이 얻는다.

### L3 — CH 경계거리 θ_b + 형태 (이 계획의 천장)

추출 1회 추가가 필요하다. 프레임당 얻을 것:

```python
from scipy import ndimage

def ch_shape_features(mask_ch, disk, radius_px):
    """mask_ch: dark0.45 AND 마스크 (H,W) bool. -> 픽셀별 깊이 + 프레임 형태 스칼라."""
    inside = mask_ch & disk
    # (1) θ_b : CH 내부에서 가장 가까운 경계까지의 거리 (픽셀 -> 도)
    depth_deg = ndimage.distance_transform_edt(inside) / radius_px * (180.0 / np.pi)
    # (2) 연결성분 : 큰 홀 1개 vs 작은 홀 여러 개
    labels, n = ndimage.label(inside)
    total = max(int(disk.sum()), 1)
    sizes = np.bincount(labels.ravel())[1:] if n else np.zeros(1)
    return depth_deg, float(sizes.max()) / total, int((sizes / total > 0.002).sum())
```

fine 12×30 격자에 셀별로 집계할 값:
- `depth_max[cell]` — 그 셀 안 CH 의 최대 경계거리 (**θ_b 대리값**)
- `depth_mean[cell]` — 면적 가중 평균 깊이
- 프레임 스칼라 3개: `big_frac`(최대 성분 면적비), `n_components`, `big_centroid_lat`

지금 모델은 "면적 0.02" 를 볼 때 `반경 5° 홀 하나`인지 `반경 1.5° 홀 10개`인지 모른다.
전자는 고속풍(600+ km/s)을 내고 후자는 거의 안 낸다.
**θ_b 는 정확히 이 차이를 하나의 스칼라로 만든다.**

> **scipy 없으면**: `ndimage` 대신 이진 침식 4~5회로 깊이 레벨 `{0,1,2,3,4}` 를 만든다.
> 해상도는 떨어지지만 신호의 성격은 같다.
>
> **런타임 위험**: EDT + label 이 프레임당 ~8ms → 이미지 2만 장이면 +3분.
> 다만 전체 재추출 자체가 30~60분이다. **오늘 제일 먼저, 백그라운드로 돌릴 것.**
> 256px 로 내려서 돌려도 CH 면적/깊이 신호는 충분하다 (속도 4배).
> 운영진이 경고한 대로 프로세스는 4개까지만 (동시 다중 프로세스가 VM 을 내린 전례 있음).

### L4 — 탄도 τ 창 확장 (5분짜리)

P9 의 `[R2] 적응형 τ` 가 왜 졌는지에 대한 가설이 하나 있다.

```python
def estimate_tau(wind):
    speed = np.clip(wind[:, -4:].mean(axis=1), SPEED_FLOOR, SPEED_CEIL)   # ← 지금 도착 중인 바람
```

**이건 틀린 속도다.** 필요한 건 *앞으로 도착할* 스트림의 전달시간이고,
그건 *그 스트림의* 속도로 정해진다. 최근 관측 속도는 **이미 지나간 스트림**의 것이다.
고속류 직전 저속 구간이면 τ 를 정반대로 밀어 버린다. R2 가 진 것이 이상하지 않다.

제대로 고치려면 2단계 추정(속도 예측 → τ 재계산 → 재추론)이 필요한데 1일에는 과하다.
**대신 τ 를 모르는 채로 전 구간을 head 에 넘긴다:**

```python
BALLISTIC_OFFSETS = (-8, -5, -2, 0, 2, 5)     # 기존 (-4, -2, 0, 2)
# 108h 기준 ± → τ ∈ [60h, 138h] 를 덮는다 (v ∈ 대략 300~690 km/s)
ADAPTIVE_AREA = False                          # R2 를 껐던 P9 채택본 유지
```

head 가 horizon embedding 과 함께 어느 오프셋이 유효한지 고르게 둔다.
`BALLISTIC_DIM` 이 1.5배가 되지만 여전히 저차원이다.

### L5 — horizon별 수축 보정 (RMSE 지표에 직접 정렬)

RMSE 최적 예측은 **조건부 평균**이다. 고분산 추정기(=지금 우리 모델)는 평균 주변으로
과하게 흔들리므로, horizon 별 기후값 쪽으로 살짝 수축시키면 RMSE 가 내려간다.

```python
# train CV 홀드아웃에서만 적합 (val 은 절대 쓰지 않는다 — P6 의 함정)
# horizon 당 파라미터 1개 = 총 12개, 표본 ~9,600 → 안전
lam_h = np.array([
    np.cov(p[:, h] - clim[h], y[:, h] - clim[h])[0, 1] / np.var(p[:, h] - clim[h])
    for h in range(12)
])
lam_h = np.clip(lam_h, 0.7, 1.0)          # 안전 상한/하한
pred_final = clim[None, :] + lam_h[None, :] * (pred - clim[None, :])
```

L1 앙상블이 이미 분산을 줄이므로 `lam_h` 는 1에 가깝게 나올 것이다.
**1에 가깝게 나오면 그 자체가 앙상블이 잘 됐다는 진단**이고, 크게 벗어나면 이득이다.
둘 다 정보다. 비용은 20분.

로컬 CV 는 §1.5 에서 반증됐으므로 **제출이 유일하게 신뢰할 수 있는 계측기**다.
5회밖에 없으므로 **"사전확률이 확실히 양수인 변경만 묶어서" 한 칸에 올린다.**
한 칸에 한 가지만 바꾸는 P9 식 규율은 여기서는 사치다.

| # | 내용 | 기대 | 판정 후 |
|---|---|---|---|
| **S1** | 앙상블만 (구 기하, A0×3 + F3×3) | 57.2~58.0 | 개선 → 바닥 확정. 악화 → **즉시 중단, P3 유지** |
| **S2** | S1 + L2 (μ 보정 + 등각 경도) | −0.3~1.0 | 악화 → L2 폐기, S1 로 복귀 |

| **S4** | 승자 + L4 (τ 창) + L5 (수축) | −0.3~1.0 | 악화 → 분리 불가하므로 통째 폐기 |

**정지 규칙.** 어느 단계든 직전 최고보다 **+0.5 이상 악화**하면 그 레버는 버리고

나쁜 제출이 순위를 끌어내리지 않는다 (§5.1 각주) — **시도 자체의 하방 위험은 없다.**

> Public 에만 맞춘 미세조정은 하지 않는다. 무적합 평균과 물리 피처는
> 둘 다 Private 에도 그대로 전이되는 종류의 개선이라 이 점에서 안전하다.

## 5. 구현 스켓치 — 앙상블 멤버 저장/복원 (재현성 필수)

```python
MEMBERS = [
    dict(name="A0_s777_e1", settings=A0_SETTINGS, seed=777, epochs=1),
    dict(name="A0_s778_e2", settings=A0_SETTINGS, seed=778, epochs=2),
    # ...
    dict(name="L3_s779_e2", settings={**F3_SETTINGS, "USE_DEPTH": True}, seed=779, epochs=2),
]

states, preds = [], []
for m in MEMBERS:
    configure(**m["settings"])                       # 파생 상수 재생성
    random.seed(m["seed"]); np.random.seed(m["seed"]); torch.manual_seed(m["seed"])
    stats = fit_stats(np.arange(len(train_inputs)))  # train 전체 (val 미사용)
    model = train_full(stats, epochs=m["epochs"], seed=m["seed"])
    states.append({k: v.cpu() for k, v in model.state_dict().items()})
    preds.append(predict_test(model, stats))         # (3868, 12)

pred = np.mean(preds, axis=0)                        # 균등가중, 적합 파라미터 0개
pred = CLIM[None, :] + LAM_H[None, :] * (pred - CLIM[None, :])          # L5
pred = np.clip(pred, PHYS_LOW, PHYS_HIGH)

torch.save({"members": states,
            "configs": [{"name": m["name"],
                         "settings": {k: str(v) for k, v in m["settings"].items()},
                         "seed": m["seed"], "epochs": m["epochs"]} for m in MEMBERS],
            "lam_h": LAM_H, "code_version": "p11"}, SUBMISSION_DIR / "model.pth")
```

**추론 전용 경로를 반드시 같은 노트북에 둘 것.** `model.pth` 를 읽어
`configs` 대로 모델을 재구성하고 `submission.csv` 를 다시 만드는 셀이 있어야
"제출 코드로 재현 가능" 조건(본선 안내 §5·§6)을 만족한다.

## 6. 만약 시간이 반밖에 없다면

우선순위를 이렇게 자른다.

1. **L1 (앙상블) — 무조건.** 이것만 해도 57.2~57.6, 대략 9~13위.
2. **L2 (μ 보정) — 30분.** 재추출 없이 되고 물리적으로 옳다는 확신이 가장 높다.
3. 나머지는 버린다.

L3(θ_b)를 못 넣으면 1위는 사실상 불가능하다. 하지만 **L1+L2 만으로도 22위 → 10위권**이고,
그건 오늘 안에 거의 확실히 잡을 수 있는 숫자다.
