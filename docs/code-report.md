## 0. 읽는 법

이 프로젝트는 **모델 계보(P1→P10)** 와 **계측기 계보(무엇을 믿고 고를 것인가)** 두 축이 얽혀 있다.
두 번째 축이 사실상 이 프로젝트의 본체다. P6까지는 validation 으로 골랐고, P7 이후로는
"validation 을 믿지 못한다"는 인식 위에서 **계측기 자체를 다시 만드는 작업**이 이어졌다.

`P8` 은 존재하지 않는다 (SpeedNet 작업이 P10 으로 번호를 옮겨 갔다).
`N1` 은 P 계열과 별도 갈래다 — 주최측 baseline 에 SpeedNet 만 이식한 최소 변경본이다.

### 과제 요약

| 항목 | 내용 |
|---|---|
| 입력 | 과거 120h(20시점×6h)의 SDO/AIA 193Å·211Å 영상 20쌍 + 태양풍 속도 20개 |
| 출력 | 이후 6h~72h 를 6시간 간격으로 **12개** |
| 지표 | horizon 별 RMSE 를 먼저 낸 뒤 **평균** (pooled RMSE 와 다름, 1.5~2.0 km/s 차이) |
| 데이터 | train 9,607 / val 1,199 / test 3,868 샘플, 512×512 8bit PNG |
| 제약 | 외부 데이터·pretrained weight·validation 학습 사용·test target 역산 전부 금지 |

### ⚠️ 데이터의 숨은 구조 — 모든 판단의 전제

샘플은 **6시간 stride 슬라이딩 윈도우**다. 연속 샘플이 입력의 19/20 을 공유한다.
실질 독립 표본은 9,607개가 아니라 **태양 자전 약 135회전분**이고,
**1 epoch ≈ 독립 데이터 20회 통과**다. 이 한 문장이 P2 이후 모든 설계 결정의 배경이다.

### ✅ 데이터 무결성 — 감사 완료 (§5.6)

| 항목 | 사실 |
|---|---|
| 결측 | **없다.** wind·target NaN 0, sentinel 0, 물리범위(200~1200 km/s) 밖 0 — 전 split |
| 이미지 | **완전하다.** 윈도우 20개 전부 고유, 중복 0, 파일 누락 0 — 전 split |
| 인덱스 방향 | `image_00`·`wind_00` 이 가장 과거, **`_19` 가 T0** (persistence RMSE 로 확정) |
| 이미지↔wind 정렬 | 오프셋 없음. CH 면적↔wind 상관 봉우리 **+96h** = 이론 전달시간과 정합 |
| wind 해상도 | **1 km/s 정수 양자화** (OMNI 원 해상도). 인접 동일값 2.23% 는 이 때문이며 fill 흔적이 아니다 |

**따라서 결측 보간·이미지 보정은 이 대회에서 개선 레버가 아니다.** 근거는 §5.6.

| 제출 | val | Public | 오프셋 | val 성격 |
|---|---|---|---|---|
| P1 | 68.408 | 62.3393 | −6.07 | val 선택 (편향) |
| **P3** | 64.203 | **58.8028** ★ | −5.40 | val 선택 (편향) |

### 순위가 통째로 뒤바뀐다

```
val 순위 :  P6(63.36) < P3(64.20) < P10(66.77) < P9(66.98) < P1(68.41)
Pub 순위 :  P3(58.80) < P9(59.22) < N1(59.73) < P6(60.20) < P10(61.79) < P1(62.34)
```

- val 이 **1위로 뽑은 P6** 은 Public 4위다
- val 이 **꼴찌 직전으로 둔 P9** 는 Public 2위다
- 맞힌 것은 **P1 이 꼴찌라는 것 하나**뿐이다

### 결정적 증거 — P9 vs P10

두 모델은 조건이 가장 가깝다. 둘 다 `epochs=1`, 둘 다 CNN 없는 격자 피처 모델,
둘 다 P9 의 개선된 CV 계측기로 epoch 를 골랐다.

| | P9 | P10 | 차이 |
|---|---|---|---|
| CV | 63.643 | 63.630 | **+0.013** (P10 우세) |
| CV 표준오차 | ±0.763 | — | — |
| val | 66.978 | 66.772 | +0.206 (P10 우세) |
| **Public** | **59.2246** | **61.7853** | **−2.56 (P9 압승)** |

**CV 는 2.56 km/s 차이를 0.013 으로 읽었고, 부호까지 반대였다.**
P9 에서 다중 시드·시간블록 폴드·대응 비교까지 붙여 만든 계측기도
**정작 우리가 구분해야 할 크기의 차이를 구분하지 못한다.**

> **이것이 이 프로젝트에서 얻은 가장 비싼 교훈이다.**
> P6 때는 "val 을 CV 로 바꾸면 된다"가 처방이었다. 이제 그 처방도 반증됐다.
> 로컬 계측기의 분해능이 **경쟁에서 중요한 차이(0.2~3 km/s)보다 크다.**

### P9 → P10 의 2.56 은 어디서 왔나 (가설, 미검증)

두 모델의 구조적 차이 중 유력한 것 순서대로:

| # | 차이 | 왜 손해일 수 있나 |
|---|---|---|
| **1** | **탄도 피처 경도 범위** — P9 `BALLISTIC_LON="all"` (전 경도) vs P10 중앙자오선 **±10° 밴드만** | 논문(IG attribution) 근거로 좁혔는데, **정보량이 크게 줄었다.** P9 의 R1 변경이 정확히 이 반대 방향이었다 |
| **2** | **원반 커버리지** — P9 전체 원반(margin 0.95) vs P10 **±60° crop** | 동쪽 림의 코로나홀은 **곧 시야로 들어올 바로 그 신호**인데 잘려 나간다 |
| 3 | 정규화 기준 — 전체 원반 중앙값 vs ±60° 영역 중앙값 | quiet-Sun 기준이 달라진다 |
| 4 | B0 = 0 고정 | test(10~12월) 평균 B0 ≈ +4°, train(1~8월) ≈ 0°. **계절과 결부된 계통 편향.** 다만 픽셀 격자도 같은 문제를 갖고 있어 단독 설명은 약하다 |

**1·2 는 둘 다 "공간 정보를 좁혔다"는 같은 방향이다.** Stonyhurst 투영 자체가 나빴다기보다
**투영과 함께 들어온 crop·밴드 축소가 손해였을** 가능성이 높다 — 하지만 분리해 재지 않았으므로 가설이다.

## 2. 버전별 상세

### baseline — `sample_code.ipynb`

주최측 제공. 512×512 PNG 를 **64×64** grayscale uint8 memory-map 으로 줄여
`(batch, time, channel, H, W)` 텐서를 3D CNN + Inception + LSTM(128) 에 넣는다.
Adam lr=1e-4, RMSE loss, ReduceLROnPlateau, 20 epoch, batch 256.

**남긴 것:** memory-map 캐시 구조, train/val/test 분리, 제출 파일 생성 루틴.
이후 모든 버전이 이 골격을 물려받았다.

---

### P1 — 기본기 정비 (Public 62.3393)

**의도:** baseline 의 명백한 손실 5가지를 한꺼번에 메운다.

| # | 변경 | 근거 |
|---|---|---|
| 1 | **잔차 예측** — `target` 대신 `target − wind_19` 학습 후 복원 | 출력이 0 근처일 때 이미 `persistence + 평균 드리프트`에서 출발 → 수렴이 빠르다 |
| 2 | **wind 브랜치 강화** — 원시값 MLP → `[값, 1차차분, 결측플래그]` GRU + 통계 9개 | L1 관측은 결손이 흔한데 baseline 이 전혀 처리하지 않았다 → **🔴 이 근거는 §5.6 에서 반증됐다. 이 데이터에 결측은 없고 결측플래그 채널은 상수다** |
| 3 | **정규화 개선** — train split 통계로 전역 표준화 | **per-image 표준화 금지.** 코로나홀은 "절대적으로 어두운" 영역이라 이미지마다 밝기를 맞추면 신호가 사라진다 |
| 4 | **손실을 공식 지표에 정렬** — `mean_h(RMSE_h)` 직접 최소화 | baseline 은 pooled RMSE 를 쓰고 있었다 |
| 5 | **해상도 64 → 128** | 스템에서 두 번 다운샘플해 연산량은 유지 |

출력단에 horizon 별 `residual_mean/std` 를 buffer 로 심어 초기 스케일을 맞췄다.

**결과:** val 68.408 / Public 62.3393. **1차 실행에서 best epoch 2, train 37 vs val 73.**
→ 과적합이 즉시 드러났고, 이것이 P2 의 출발점이 됐다.

### P2 / P2a — 과적합 억제 (미제출)

**의도:** P1 의 best epoch 2 를 진단하고 대응한다. 원인은 **슬라이딩 윈도우 구조**로 확정됐다.

| # | 변경 | 내용 |
|---|---|---|
| 6 | **증강** | 밝기/대비 지터, 평행이동, 가우시안 노이즈, cutout |
| 7 | **용량 축소** | `flatten(2048)` → (위도, 경도) 격자 평균 풀링 `POOL_GRID=(1,4)` = 512 |
| 8 | **정규화 강화** | dropout 0.2→0.4, weight decay 1e-4→1e-3 |
| 9 | **`USE_IMAGES` 스위치** | 영상 브랜치의 실제 기여도를 재는 ablation 장치 |

> **🔴 좌우 반전 증강 금지** — 태양 자전 방향(동→서)이 뒤집혀 물리가 깨진다.
> 이 규칙은 P10 까지 그대로 유지된다.

경도를 보존한 `(1,4)` 풀링은 **경도가 도달 시간을 결정하기 때문**이다 (위도는 접었다).

**결과:** val 65.663 (P1 대비 −2.75), best epoch 5. 정규화는 작동했지만
train 39.5 / val 72.6 으로 **여전히 과적합**. → "3D CNN 이 물리를 배우는 대신 train set 을 외운다"

### P3 — 물리 피처로의 전환 (Public 58.8028) ★ 최고 제출

**의도:** CNN 을 포기하고 **저차원 물리 피처**로 간다.

**근거 — Collin et al. 2025 (Space Weather):** 코로나홀 면적을 격자 binning 한
소수의 물리 피처 + 단순 회귀로 최신 DNN 과 MHD 시뮬레이션을 모두 이겼다 (timeline RMSE 68.1).
논문 인용: *"a small number of physical features explains most of the solar wind variation"*

**구현:**

1. **원반 검출** — train 평균 영상에서 중심/반지름 추정, 림 밝아짐을 피해 5% 축소 (`DISK_MARGIN=0.95`)
2. **코로나홀 마스크** — 원반 내부 중앙값 대비 `CH_THRESHOLD_RATIO=0.45` 보다 어두우면서
   **193·211 두 채널 모두에서 어두운** 픽셀만 인정 (필라멘트 오검출 억제)
3. **격자 binning** — `CH_GRID=(3,5)` 셀별 CH 면적 비율

**★ 탄도 정렬 (ballistic alignment) — 이 대회 고유 설계, 논문에 없음**

전달 시간 τ = 1AU/v. horizon h 타깃의 근원 시각은 `T0 + h − τ`.

| horizon | v=500 기준 근원 | 윈도우 내 인덱스 |
|---|---|---|
| 6h | T0 − 77h | 6.15 |
| 72h | T0 − 11h | 17.15 |

**5일 윈도우가 모든 horizon 의 근원 시각을 덮는다** — 문제 설계가 그렇게 되어 있다.
속도 3개(350/500/700)로 근원 시각을 역산해 그 시점의 중앙자오선 CH 면적을 선형보간한다.

**head 는 12개 horizon 에 가중치를 공유**하고 horizon embedding + 해당 horizon 의 탄도 피처로만
구분한다. horizon 별 별도 head 대비 파라미터가 12배 적어 정규화 효과가 크다.

**`USE_CNN = False`** — 3D CNN 영상 브랜치를 껐다. 주석에 "과적합 주범"이라 명시돼 있다.

**결과:** val 64.203 / **Public 58.8028 — 리더보드 2위.** 단일 모델이다.

**규정상 배제한 것 (Collin 논문에 있으나 못 쓰는 것):**
- 27일 전 태양풍 → 입력이 120h 뿐
- 흑점수 N_SS, 지구 헬리오위도 α → **외부 데이터 = 실격**
- **Box-Cox 분포 변환** → 논문 명시: HSS peak 향상은 **timeline 성능 저하의 대가**.
  우리 지표가 timeline RMSE 이므로 **쓰면 손해**

#### 🔴 여기서 프로젝트의 핵심 교훈이 나온다

**로컬↔Public 오프셋이 상수가 아니다.**

| 제출 | 구성 | val | Public | 오프셋 |
|---|---|---|---|---|

오프셋이 **단조로 줄어든다.** val 을 깎을수록 그 수치가 진짜 성능 대비 낙관적으로 치우쳤다는
뜻이다. 검증 과적합의 교과서적 지문이다.

| 구간 | val 개선 | Public 개선 | 실현율 |
|---|---|---|---|
| P1 → P3 | 4.205 | 3.537 | **84%** |
| P3 → P6 | 0.846 | **−1.393** | **−165%** |

**왜 val 이 이렇게 됐나 — 세 가지가 겹쳤다.**

1. **가중치를 val 로 적합하고 같은 val 로 평가했다.** 자유도 7멤버 × 12 horizon = **84개**. 완전한 in-sample.
2. **체크포인트도 val 로 골랐다.** 멤버당 50회 이상, 7멤버면 수백 번의 선택이 val 위에서 일어난다.
3. **val 의 실질 표본이 작다.** 1,199 × 6h = 0.82년 ≈ **태양 자전 11회**. 84개 파라미터를 그 위에 적합했다.

**NNLS 가 신호가 아니라 노이즈를 적합한 증거 — 같은 설정 재실행인데 가중치가 뒤집힌다 (36h):**

| | m5 | m6 | m7 |
|---|---|---|---|
| Trial1 | 0.44 | **0.56** | **0.00** |
| Trial2 | 0.469 | **0.088** | **0.444** |

m1~m5 는 seed/dropout 만 다른 near-duplicate 라 상관 0.99+ 다. 공선성 있는 후보군에
NNLS 를 걸면 하나만 살아남는다. 5시드 평균의 분산 감소를 버리고 m5 하나의 특이성을 test 에 실었다.

**시드 편차 = 0.78~0.90 km/s** 를 여기서 처음 측정했다.
→ P3/P5-T1/P5-T2 비교가 전부 노이즈였음이 사후 확인됐다.

### P9 — 계측기의 신뢰도를 먼저 확보 (실행 완료)

**의도:** P7 의 사다리 자체에 결함이 있다고 보고 **계측 방법론을 다시 짠다.**

#### P7 사다리의 결함 4개와 대응

| # | P7 | P9 |
|---|---|---|
| **A** | F 단계가 gather·양방향·속도확장 **3개를 동시** 변경. 게다가 B 에서 3개로 바꾼 속도를 F 에서 6개로 또 바꿔 B 의 결론까지 오염 | **한 칸에 한 가지만** — 13칸으로 분해 |

| **C** | 폴드 분산만 (`fold_se`) | **시드 3개 × 폴드** 결합 표준오차. 이 규모 모델에서 시드 분산은 폴드 분산과 비슷하거나 크다 |
| **D** | 사슬을 샘플 수 기준 균등 배치 (시간 무관) | **시간 연속 블록**. test 는 미래 계절이므로 이쪽이 일반화 격차를 잘 반영. `forward`(전진 검증) 모드도 제공 |

#### 새 개선안

**[R2] 적응형 전달 시간** — P7 은 모든 샘플에 같은 지연 108h 를 썼다. 108h 는 **모집단 평균**이고
고속 스트림 샘플의 실제 전달 시간은 70h 아래로 떨어진다. 관측된 최근 4스텝 평균 속도로
샘플별 τ 를 만든다:

```
τ_i = TAU_SCALE × (1 AU / v̂_i),   TAU_SCALE = 1.0775
```

`TAU_SCALE` 은 train 평균 속도(414.6 km/s)에서 정확히 108h 가 되도록 맞춘 보정 계수다.
EDA 의 경험적 최적을 유지한 채 샘플별로만 흔든다.

**[R2] 관측창 이탈 플래그** — 고정 τ 에서는 clip 여부가 horizon 만의 함수라 horizon embedding 과
중복이어서 무의미했다. 적응형이 되면 같은 horizon 이라도 샘플마다 clip 여부가 달라져 **비로소 정보가 된다.**

**[R1] 탄도 경도 확장** — `BALLISTIC_LON="all"`. gather 경로(양방향 GRU 은닉)는 시퀀스 전체를
섞은 값이라 시간 국소성이 흐려지는데, 원시 셀 값을 소스 시각에서 직접 뽑으면 날카로운 신호가 하나 더 들어간다.

#### 판정 방법 — 대응 표본

두 config 을 **같은 폴드·같은 시드**에서 돌린다. 독립 표본처럼 비교하면 "그 폴드가 원래 어려웠다",
"그 시드가 원래 나빴다"는 공통 성분이 오차에 남는다. 짝지어 빼면 상쇄된다.

```
d(f,s) = RMSE_G3(f,s) − RMSE_F3(f,s),    SE = sd(d) / √(F·S)
```

`paired_se` 와 `unpaired_se` 를 나란히 출력한다. 보통 3~5배 차이가 나고 그만큼 실행 횟수를 줄인다.
`|dCV| > 2 × paired_se` 일 때만 개선/악화로 보고, 그 안이면 **차이없음**.

#### Stonyhurst 투영이 준 것 — 이 대회 한정 이득

P3~P9 의 CH 격자는 **이미지 픽셀 좌표를 그대로 등분**한 것이다. 그건 정사영이라
경도 φ 에서 면적이 `cos φ` 만큼 **단축**된다 — φ=60° 에서 실제의 절반으로 세고 있었다.

1. **면적이 진짜 일면 면적이 된다**
2. **자전이 순수한 가로 평행이동이 된다** (6h 당 3.545°)
3. **마지막 관측 이후를 외삽할 수 있다** — 지금 동쪽 경도 −φ 에 있는 CH 는 φ/Ω 시간 뒤
   중앙자오선을 지난다. P7 이 인덱스를 19 로 clamp 해 죽여 놓았던 구간이다
4. **논문의 "중앙자오선 ±10°" 를 그대로 쓸 수 있다** — 픽셀 좌표에서는 정의조차 안 되던 양


**→ 논문의 SpeedNet CNN-LSTM 3종이 맵 없는 격자 피처 대조군을 이기지 못했다.**
자전 외삽도 켠 쪽이 지거나 무의미했다.

**제출 결과: Public 61.7853** (2026-08-19 23:56). **P1 이후 최악이고 P3 에 2.98 뒤졌다.**
CV 는 P9 보다 0.013 좋다고 했는데 Public 은 2.56 나빴다 — §1.5 의 결정적 증거가 이것이다.
사다리가 채택한 것은 CNN 이 아니라 `feature` 변형이었으므로, 이 점수는
**SpeedNet 아키텍처가 아니라 Stonyhurst 전처리 파이프라인의 성적**이다.

### N1 — baseline 최소 이식본 (별도 갈래)

**의도:** P 계열의 누적 자산을 전부 걷어내고, **주최측 baseline 에 SpeedNet 만** 얹는다.

## 4. 계측기의 진화 — 이 프로젝트의 진짜 축

| 세대 | 판단 기준 | 문제 |
|---|---|---|
| P1~P5 | validation 단일 수치 | 시드 편차(0.8~0.9)를 몰라 노이즈를 개선으로 오독 |
| P6 | validation + NNLS in-sample | val 로 적합하고 같은 val 로 평가. 자유도 84개 |
| P7 | train 사슬 CV (5폴드, 1시드) | 사다리 한 칸이 여러 변경을 동시에 함. epoch 이중 선택 |
| P9 | 시간블록 폴드 × 3시드, 대응 비교, 기준 epoch 고정 | **P10 과의 2.56 차이를 0.013 으로 읽음 (§1.5)** |
| P10 | 위와 동일 + 변형 비교 | 위와 동일 |

**🔴 개정: 계측기 개선 서사는 P9/P10 Public 으로 반증됐다.**
P6 의 처방은 "val 을 CV 로 바꾼다"였고 P9 는 그 CV 를 정밀화했다. 그런데 그 정밀한 CV 가
**Public 2.56 차이를 0.013 으로, 그것도 반대 부호로** 읽었다. 계측기를 정교하게 만드는 방향은
여기서 수확이 끝났다고 봐야 한다.

**측정된 노이즈 바닥의 변천:**

- P6 에서 처음 측정한 **시드 편차 0.78~0.90 km/s**
- val 자체의 표본 오차를 합치면 실제 판단 임계는 **3 km/s** (HANDOFF §5.1 개정)
- 제출 CSV 간 test 예측 불일치로 재보면: val 1.6 차이나는 두 모델이 test 에서 **26 km/s RMS** 로 다른 함수

| 비교 | val 차이 | test 예측 RMS 불일치 |
|---|---|---|
| P6-T1 vs P6-T2 (같은 설정 재실행) | 0.21 | 4.60 |
| P3 vs P6-T1 | 0.85 | 22.71 |
| P5-T2 vs P6-T1 | 1.60 | **25.94** |

**→ P3→P6 의 val 차이 0.85 는 통째로 노이즈 안에 들어간다. 측정된 적이 없는 순위였다.**

### 5.2. 확정된 것

1. **가장 잘 전이된 모델은 여전히 P3** — 단일 모델, CH-only, CNN 없음. Public 58.8028.

3. **물리 피처(CH 격자 + 탄도 정렬)가 이 문제의 주력이다.**
4. **🔴 로컬 계측기로는 이 경쟁의 승부를 못 가린다.** val 이 순위를 뒤집었고(§1.5),

   **P6 때 얻은 "val 대신 CV" 처방은 이제 함께 반증됐다.**
5. **공간 정보를 좁히는 방향은 손해였다.** P10 이 중앙자오선 ±10° 밴드와 ±60° crop 으로
   좁혔다가 2.98 잃었고, 전 경도를 쓴 P9 가 2.56 앞섰다. 논문의 IG attribution 결론을
   **피처 설계로 그대로 옮긴 것이 이 데이터에서는 역효과**였다 (가설, §1.5).
6. **데이터는 완전하다 — 결측 처리는 레버가 아니다.** wind·target·이미지 전 split 무결.
   P1 이래 넣어 온 `valid` 플래그는 상수이므로 **GRU 입력의 죽은 채널**이다 (§5.6).
7. **이미지는 시간순으로 들어가고 있다.** 윈도우 내부 `_00`→`_19` 가 과거→T0 이고,
   이미지축과 wind 축 사이에 정렬 오프셋이 없다. **탄도 정렬의 전제는 옳다** (§5.6).

### 5.5. P10 의 Stonyhurst 투영에 대한 유보 (개정)

투영은 **면적 계산을 물리적으로 옳게** 만들었지만, 사다리는 그 이득을 **분리해서 재지 못했다.**
A0 와 A1 둘 다 투영 위에서 돌기 때문이다.

**그리고 이제 Public 이 하나 더 말해 준다 — 투영 파이프라인 전체로는 2.98 손해였다.**
다만 이 숫자는 투영·crop·경도밴드·정규화 기준이 전부 섞인 값이라
**투영 자체의 죄인지는 여전히 알 수 없다.** N1(같은 투영, ±75° 로 더 넓게, 밴드 대신 스칼라)이
P10 보다 2.05 좋다는 사실이 "투영이 아니라 좁힌 것이 문제"라는 쪽을 지지한다.

### 5.6. 데이터 무결성 감사 (2026-08-20)

**동기.** "결측을 어떻게 보간할 것인가" 와 "이미지가 정말 시간순으로 들어가는가" 두 물음이
제기됐다. 둘 다 사실이면 설계 전반을 흔드는 문제이므로 **추측 대신 데이터로 닫았다.**

**방법.** `eda_missing_and_order.py` 를 대회 서버에서 실행했다. 출력은 `print` 요약뿐이고
원본을 복사·압축·분할 저장하지 않으므로 2026-08-18 운영진 공지에 저촉되지 않는다.

#### 결과

| 검사 | 결과 | 판정 |
|---|---|---|
| **A1** 결측·sentinel | NaN 0 · inf 0 · sentinel(9999/-1/0 등) 0 · 물리범위 밖 0 — 전 split | ✅ 결측 없음 |
| **A2** 계단(반복값) 구간 | 인접 동일값 2.23%, 최장 런 3스텝 (`{2: 223, 3: 1}`) | ✅ fill 흔적 아님 |
| **A3** `valid` 플래그 | 전 split 평균 **1.000000**, 0 인 원소 0개 | 🔴 **상수 = 죽은 채널** |
| **B1** 인덱스 방향 | persistence 공식 RMSE — `wind_19` **81.46** ≪ `wind_09` 119.52 < `wind_00` 124.93 | ✅ `_19` = T0 확정 |
| **B2** 이미지↔wind 정렬 | CH 면적 상관 봉우리 **+96h** (+0.1203, 함의 433 km/s) | ✅ 오프셋 없음 |
| **B3** 이미지 결측 | 윈도우 20개 전부 고유(중복 행 0) · 파일 누락 0 — 전 split | ✅ 완전 |

#### A2 를 하마터면 오독할 뻔했다 — wind 는 정수다

출력값이 전부 `341.00`, `358.00`, `248.00` 이다. **wind 는 1 km/s 정수로 양자화**돼 있다
(OMNI 원 해상도). 스크립트의 "반복 1% 초과면 fill 의심" 임계는 이를 예상하지 못한 것이었다.

- 인접 동일 **쌍** = 223×1 + 1×2 = 225 / 전체 인접쌍 10,111 = **2.23%**
- 6h 변화량 std ≈ 26.5 km/s (= `wind_19` 의 6h persistence RMSE).
  가우시안이라면 Δ=0 확률 ≈ 1/(26.5·√2π) ≈ **1.5%**
- 태양풍 6h 변화 분포는 0 근처가 뾰족하므로 실제 밀도는 그보다 높다 → **2.23% 는 자연값**

결정적 근거는 **런 길이 분포**다. forward-fill 이라면 실제 L1 공백(수 시간~수 일)을 메운 것이므로
4·5·10스텝의 **두꺼운 꼬리**가 나와야 한다. 그런데 길이-3 런이 train 전체에 **단 1개**다.
독립 가정(p=0.0223)만으로도 5개는 나와야 하는 수치이므로, fill 이 아니라 오히려 반(反)군집이다.

> **교훈 — 정수 양자화된 시계열에서 "인접 동일값 비율"은 결측 판별 지표로 쓸 수 없다.**
> 반드시 **런 길이 분포의 꼬리**를 봐야 한다.

#### 🔴 186h 음의 봉우리는 아티팩트다 — 세 번째로 쫓지 말 것

감사 스크립트가 처음에 보고한 "최대 상관 lag = 186h (223 km/s)" 는 `abs()` 로 최대를 찾은
결과였다. **물리적으로 CH 면적이 크면 태양풍이 빠르므로 상관은 양수여야 한다.**

```
 84h  +0.1010   (495 km/s)
 96h  +0.1203   ← 물리 봉우리 (433 km/s)
108h  +0.1061   (385 km/s)   ← P7 EDA 가 채택한 값
```

96h 가 이론 전달시간 110h(평균 379.5 km/s)보다 짧은 것은 **정상**이다. 상관을 만드는 주체가
코로나홀發 고속풍이라 봉우리가 평균보다 빠른 쪽으로 당겨진다.

**주목할 점은 이 186h 가 P7 EDA 에서도 똑같이 나왔다는 것이다** — `186h / 223 km/s / corr −0.280`
(§P7 EDA 표). 표본·밴드 폭·기준(잔차 vs 원값)이 전부 다른데도 **둘 다 테스트 lag 범위의 끝단**에
붙어 나왔다. 저주파 추세가 지배하는 구간의 전형적 아티팩트다. P7 은 `MIN_LAG_HOURS` 로
우연히 회피했으나, 근거가 기록되지 않아 이번에 다시 걸려들 뻔했다.

#### 한계

B2 는 **3스텝(18h) 이상의 큰 어긋남만 배제**한다. 봉우리가 84~120h 로 넓고 corr 이 0.12 로
약해서 **1스텝(6h) 오프셋은 이 검사로 잡히지 않는다** (§5.4-11).

#### 시사점

1. **결측 보간은 이 대회의 개선 레버가 아니다.** 데이터가 완전하므로 이 방향은 닫혔다.
2. **`fill_wind()` 와 `valid` 채널은 죽은 코드다.** `nn.GRU(3, 96)` → `nn.GRU(2, 96)` 정리가
   가능하지만, 상수 입력은 중복 bias 로 작동할 뿐이라 **성능 영향은 소수점 아래**로 예상된다.
   정직하게 말해 이것은 성능 개선안이 아니라 코드 정리다.
3. **탄도 정렬의 전제(`19` = T0, 이미지↔wind 정렬)는 옳다.** P3 이래의 물리 피처가
   잘못된 시점을 보고 있었을 가능성은 배제됐다.
